feat: auto-save and resume the single game

The one game now survives the app closing. It is saved automatically
whenever the game value changes and restored once on mount, so neither
player has any save to think about and no save UI to learn. Because
serialisation carries the full history, undo still reaches the start
after a resume and a finished game returns finished.

Storage is a small injected GameStorage seam (read/write one string).
The save/restore logic lives in a plain-Node module that knows nothing
of React or Expo and takes the storage as a parameter, so the whole
round trip is verified device-free through an in-memory fake. The
device-backed AsyncStorage adapter is isolated in its own file, away
from the tested logic. Untrusted storage — empty, garbage, truncated or
an older format — yields a fresh, playable game rather than a broken
screen.

Adds @react-native-async-storage/async-storage (Expo-supported) for the
single-key device store.
